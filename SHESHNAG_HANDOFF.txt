REQUIRED SECTION 6 — BATCH SIZE CHECK
================================================================================
Verify the scale before submitting:

  ×
  50 independent generations per question
  =
  50,000 total batch requests

Command to verify:
  python scripts/validate_batch.py

Output must state:
  VALIDATION PASSED
  Total requests: 50000
  Expected:       50000
  Questions:      1000
  Gens/question:  50

CRITICAL ARCHITECTURAL NOTE:
The batch consists of 50 separate JSONL requests for each question.
It does NOT use `n=50` or `n > 1` in API requests because Sheshnag's Ollama
backend explicitly rejects `n > 1`. Each line has a unique custom ID:
  gsm8k_q000001_g0001
  ...
  gsm8k_q001000_g0050

REQUIRED SECTION 7 — SUBMISSION COMMAND
================================================================================
Command:
  python scripts/submit_sheshnag.py

What this does:
  - Validates credentials from `.env`
  - Verifies that the configured model exists on the deployment
  - Uploads `batch/generated/sheshnag_batch.jsonl`
  - Creates the batch job with endpoint `/v1/chat/completions` and window `24h`
  - Automatically records batch metadata into `batch/results/batch_info.json`:
    {
      "batch_id": "<batch_id>",
      "file_id": "<file_id>",
      "model_id": "<model_id>",
      "batch_file": "..."
    }
  - Begins status polling every 30 seconds

What success looks like:
  Verifying model '<model_id>'...
  Model '<model_id>' is available.
  Uploading batch file: batch/generated/sheshnag_batch.jsonl
  Uploaded batch file. File ID: file-xxxxxx
  Creating batch job...
  Created batch. Batch ID: batch_xxxxxx
  Status: validating
  Batch info saved to: batch/results/batch_info.json
  BATCH ID: batch_xxxxxx
  Polling for completion (interval: 30s)...

Record the BATCH ID in your notes immediately!

REQUIRED SECTION 8 — MONITORING & STATUS CODES
================================================================================
During polling, you will observe the standard OpenAI Batch lifecycle:

  1. `validating`
     Sheshnag is verifying JSON syntax, token limits, and schema.
     This is NORMAL and not an error.

  2. `validated`
     Batch passed pre-flight checks and is queued in the job scheduler waiting
     for GPU worker capacity. This is NORMAL.

  3. `in_progress`
     GPU workers are actively executing completions.

  4. `completed`
     All completions finished successfully. Results are ready to download.

  5. `failed`
     Job failed. Check `batch/results/batch_info.json` and terminal log.
     Do not spam resubmissions; see Troubleshooting below.

Check status on demand anytime:
  python scripts/submit_sheshnag.py --status <BATCH_ID>

REQUIRED SECTION 10 — EVALUATION
================================================================================
Command:
  python scripts/evaluate.py

What this does:
  1. Parses raw JSONL model completions (`FINAL_ANSWER:`, `####`, `\boxed{}`)
  2. Normalizes numerical answers (stripping commas, currency symbols, trailing units/zeros)
  3. Saves parsed table to `results/parsed/generations.csv`
  4. For every question, deterministically shuffles the 50 generations using seed (42 + question_id)
  5. Evaluates plurality/majority voting at each budget:
     N = 1, N = 3, N = 5, N = 10, N = 20, N = 50
  6. Compares voted answer against the gold ground truth
  7. Outputs wide and long evaluation tables to `results/final/`
  8. Prints the accuracy table directly to the console

Notice: No additional Sheshnag runs are needed for N=1,3,5,10,20,50.
All inference budgets are derived locally from the single 50-generation pool.

================================================================================
REQUIRED SECTION 11 — FINAL ANALYSIS & FIGURE GENERATION
================================================================================
Command:
  python scripts/analyze.py

What this does:
  1. Calculates 95% bootstrap confidence intervals (10,000 question-level resamples)
  2. Computes marginal accuracy gains between successive N values:
     Δ(3)  = Accuracy(3)  - Accuracy(1)
     Δ(5)  = Accuracy(5)  - Accuracy(3)
     Δ(10) = Accuracy(10) - Accuracy(5)
     Δ(20) = Accuracy(20) - Accuracy(10)
     Δ(50) = Accuracy(50) - Accuracy(20)
  3. Computes gain per additional generation to pinpoint diminishing returns
  4. Generates 3 publication-quality figures:
     - results/analysis/figures/accuracy_vs_generations.png
     - results/analysis/figures/marginal_gain.png
     - results/analysis/figures/accuracy_vs_budget.png
  5. Saves summary tables to:
     - results/analysis/summary.csv
     - results/analysis/summary.json
     - results/analysis/marginal_gains.csv
  6. Automatically updates `reports/results_summary.md` with final numbers

REQUIRED SECTION 13 — TROUBLESHOOTING
================================================================================

Problem: "Invalid API key" / Authentication Error (401)
  Check:
  - Verify `SHESHNAG_API_KEY` in `.env` has no leading/trailing spaces or quotes.
  - Verify that the API key was not copied with line breaks.
  - Run `python scripts/submit_sheshnag.py --check-models` to test auth independently.

Problem: "Connection refused" / Wrong Base URL (404/ECONNREFUSED)
  Check:
  - Verify `SHESHNAG_BASE_URL` in `.env` includes `https://` and ends in `/v1`.
  - Ensure there is NO trailing slash after `/v1`.
  - Example of correct URL: `https://sheshnag.university.edu/v1`
  - Example of incorrect URL: `https://sheshnag.university.edu/v1/`

Problem: "Model not found" (404)
  Check:
  - Run `python scripts/submit_sheshnag.py --check-models`.
  - Copy the exact string ID of one of the listed models into `SHESHNAG_MODEL_ID` in `.env`.
  - Do NOT invent or guess model names.

Problem: Batch file validation fails
  Check:
  - Run `python scripts/validate_batch.py`.
  - Read the numbered error list. Common causes:
    * Batch file was generated with a placeholder model ID.
    * Re-run `python scripts/create_batch.py` after updating `.env`.

Problem: Batch remains in `validated` for a prolonged period
  Explanation:
  - `validated` means your 50,000-line request passed schema checks and is
    waiting in the university cluster's queue for available GPU nodes.
  - This is expected behavior during peak cluster usage. Do NOT cancel or resubmit.

Problem: Batch status becomes `failed`
  Check:
  - Check error details: if available, `sheshnag_errors.jsonl` will be saved in `results/raw/`.
  - Check cluster GPU status or contact the cluster admin with the BATCH ID.
  - Do NOT resubmit immediately without identifying the failure reason.

Problem: Missing results file after job completion
  Check:
  - Run `python scripts/download_results.py --batch-id <BATCH_ID>` explicitly.
